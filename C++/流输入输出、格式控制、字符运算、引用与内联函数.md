# 流输入输出、格式控制、字符运算、引用与内联函数

创建日期：2026-09-29

本篇辨析 5 个容易记混的点，先给结论：

| # | 说法 | 结论 |
| --- | --- | --- |
| 1 | 流输入、输出 | ✅ 用 `<<` / `>>` 操作流对象，返回流引用，所以能连着写 |
| 2 | 格式控制 | ✅ 用 `<iomanip>` 的操纵符；`setw` 只影响下一次输出 |
| 3 | 字符数据可以与整型数据进行运算 | ✅ `char` 本质就是整型，运算时提升为 `int` |
| 4 | 引用不是变量，自身没有地址 | ⚠️ 基本正确，但要补一句：语言层不提供"引用自己的地址"，而实现上常常占存储 |
| 5 | 内联函数用 `inline` 声明不能使用循环 | ❌ 不成立，标准从未禁止，`inline` 只是建议 |

## 1. 流输入、输出

### 1.1 什么是"流"

- **是什么**：流（stream）是对"字节序列"的抽象，把**数据从哪里来 / 往哪里去**和**怎么读写**解耦。程序不用关心对面是键盘、文件还是网络，只管往流里读、往流里写。
- **四个标准流对象**（都在 `<iostream>` 里，位于 `std` 命名空间）：

| 对象 | 含义 | 缓冲 |
| --- | --- | --- |
| `std::cin` | 标准输入（键盘） | 有缓冲 |
| `std::cout` | 标准输出（屏幕） | 有缓冲 |
| `std::cerr` | 错误输出 | 每个操作后立即刷新（unitbuf） |
| `std::clog` | 日志输出 | 有缓冲 |

- 一句话：**流是"数据通道"的抽象，`cin` / `cout` 就是标准输入输出这两个通道的名字。**

### 1.2 `<<` 与 `>>`

| 运算符 | 名字 | 数据流向 | 例子 |
| --- | --- | --- | --- |
| `<<` | 插入运算符（insertion） | 数据 → 流 | `std::cout << x` |
| `>>` | 提取运算符（extraction） | 流 → 数据 | `std::cin >> x` |

- **为什么能连着写**：这两个运算符都**返回流对象自身的引用**。所以

```cpp
std::cout << a << b;      // 等价于 (std::cout << a) << b
std::cin  >> a >> b;      // 等价于 (std::cin  >> a) >> b
```

- **为什么不用写类型**：运算符重载会按操作数的类型自动选择对应版本，所以是**类型安全**的，不像 `printf` / `scanf` 那样需要格式串、也不容易因为类型不匹配而出错。
- 一句话：**`<<` 是"往流里插"，`>>` 是"从流里提"，两者都返回流引用，所以能链式书写。**

### 1.3 `>>` 的四个关键行为（易错）

1. **自动跳过前导空白**（空格、Tab、换行）。
2. **以空白为分隔**：`std::cin >> s` 只能读到一个"单词"，读不到带空格的整行。
3. **按目标类型解析**：`std::cin >> n` 遇到非数字字符就停止，并把那个字符留在缓冲区里。
4. **会进入失败状态**：读到不匹配的内容时流进入 fail 状态，**之后的读取会一直直接失败**，必须先 `std::cin.clear()` 清状态、再清缓冲区。

**最容易踩的坑：`>>` 与 `getline` 混用**

```cpp
#include <iostream>
#include <string>

int main() {
    int n;
    std::string line;

    std::cin >> n;                    // 只把数字读走，换行符还留在缓冲区
    std::cin.ignore(1, '\n');         // 吃掉那个换行符，否则下一句会读到空串
    std::getline(std::cin, line);     // 现在才能读到完整的一行

    std::cout << n << " | " << line << '\n';
}
```

- **`std::endl` 与 `'\n'` 的区别**：`std::endl` 除了换行还会**刷新缓冲区**（flush）。频繁使用会明显拖慢输出速度，只想要换行就写 `'\n'`。
- 一句话：**`>>` 跳过空白、按类型解析、失败后"卡住"；和 `getline` 混用时记得先 `ignore` 掉遗留的换行符。**

## 2. 格式控制

### 2.1 两条路径

- **成员函数**（老式写法，啰嗦）：`std::cout.width(n)`、`std::cout.precision(n)`、`std::cout.setf(...)` / `unsetf(...)`。
- **操纵符（manipulators）**（推荐）：直接夹在 `<<` 之间写，需要 `#include <iomanip>`。

### 2.2 常用操纵符

| 操纵符 | 作用 | 是否只影响下一次输出 |
| --- | --- | --- |
| `setw(n)` | 设置字段宽度（默认右对齐、空格填充） | **是**，只作用于紧随其后的那一个输出项 |
| `setfill(c)` | 设置填充字符 | 否，持续有效 |
| `left` / `right` / `internal` | 左对齐 / 右对齐 / 符号与数值分开对齐 | 否 |
| `setprecision(n)` | 设置精度 | 否 |
| `fixed` | 定点表示 | 否 |
| `scientific` | 科学计数法 | 否 |
| `showpoint` | 强制显示小数点 | 否 |
| `hex` / `oct` / `dec` | 十六 / 八 / 十进制整数输出 | 否 |
| `showbase` | 显示进制前缀（`0x`、前导 `0`） | 否 |
| `boolalpha` | `bool` 输出成 `true` / `false` | 否 |

### 2.3 两个最容易踩的坑

- **`setw` 是一次性的**：它只对**紧接着的那一个**输出项生效，后面的输出立刻回到默认宽度。而其它操纵符大多是"粘性"的，一旦设置就一直有效。
- **`setprecision` 的含义会变**：
  - 默认（一般格式）下表示**有效数字位数**；
  - 用了 `fixed` 或 `scientific` 之后表示**小数点后的位数**。

```cpp
#include <iostream>
#include <iomanip>

std::cout << std::setw(6) << std::setfill('0') << 42 << '\n';  // 000042
std::cout << std::setw(6) << 42 << '\n';                       // 000042（setfill 是粘性的）
std::cout << 42 << '\n';                                       // 42    （setw 已失效）

std::cout << std::setprecision(4) << 3.1415926 << '\n';        // 3.142（4 位有效数字）
std::cout << std::scientific << 3.1415926 << '\n';             // 3.1416e+00（4 位小数）

std::cout << std::hex << 255 << '\n';                          // ff
std::cout << std::dec << 255 << '\n';                          // 255（改回十进制）
```

- 一句话：**格式控制改的是"流对象自身的状态"，除了 `setw` 只管一次，其它设置会一直留着，所以用完记得改回来。**

## 3. 字符数据可以与整型数据进行运算

### 3.1 结论

**正确。** `char` 在 C++ 里就是一种**整数类型**（占 1 字节的整型），它存的不是"字符"本身，而是字符的**编码值**。所以它当然可以和整数一起做加减乘除。

### 3.2 运算时发生了什么

- 参与算术运算时，`char` 会先做**整型提升（integral promotion）**变成 `int`，再参与运算。
- `'A' + 1` 的结果是 **`int` 类型的 66**，不是 `char`；要变回字符必须转换：`(char)('A' + 1)`。

常用编码值：

| 字符 | 十进制 | 备注 |
| --- | --- | --- |
| `'0'` | 48 | 数字字符的起点 |
| `'A'` | 65 | 大写字母起点 |
| `'a'` | 97 | 小写字母起点 |
| `' '` | 32 | 空格 |

### 3.3 三个常用技巧

```cpp
char c = 'A';

std::cout << c + 1 << '\n';          // 66  —— 结果是 int，打印出数字
std::cout << (char)(c + 1) << '\n';  // B   —— 转回 char 才是字符

std::cout << '5' - '0' << '\n';      // 5   —— 字符数字转数值
std::cout << 'a' - 'A' << '\n';      // 32  —— 大小写编码相差 32

char upper = 'a' - 32;               // 'A'，小写转大写
char lower = 'A' + 32;               // 'a'，大写转小写
```

### 3.4 四个易错点

- **`'5'` 和 `5` 差 48**：前者是字符（编码值 53），后者是整数。混用就会出现"输入 5 却算成了 53"这类错误。
- **`'A'` 与 `"A"` 完全不同**：`'A'` 是 `char`（1 字节）；`"A"` 是字符串字面量，类型是 `const char[2]`，末尾还有一个 `'\0'`。
- **`char` 的符号性依赖实现**：可能是 `signed char`（−128 ~ 127），也可能是 `unsigned char`（0 ~ 255）。ASCII 范围内都没问题，但处理大于 127 的字节（例如中文 UTF-8 的字节）时两者结果不同，建议用 `unsigned char` 或 `std::byte`。
- **溢出**：`char` 只有 8 位。若是有符号的 `char c = 127; ++c;` 属于溢出（有符号整型溢出是未定义行为）。

- 一句话：**`char` 就是"小整数"，参与运算时提升成 `int`；记住 `'5' - '0' = 5`、`'a' - 'A' = 32` 这两个式子就够用了。**

## 4. 引用不是变量，自身没有地址

### 4.1 结论

**基本正确，但需要补一句限定。** 引用（reference）是给已有对象起的**别名**，语言层面不把它当独立对象看待；但"不占存储"并不是标准保证的。

### 4.2 引用的三条硬规则

1. **定义时必须初始化**，不存在"空引用"。
2. **一旦绑定就不能改绑**。写 `r = b;` 不是让 `r` 指向 `b`，而是**给 `r` 所绑定的那个对象赋值**。
3. **对引用取地址 `&r`，得到的是被引用对象的地址**，与 `&a` 完全一样 —— 这就是"引用自身没有地址"这句话的来历。

### 4.3 代码验证

```cpp
#include <iostream>

int main() {
    int a = 10, b = 20;
    int& r = a;                 // r 是 a 的别名，必须在这里初始化

    r = b;                      // 等价于 a = 20；引用并没有"改绑"到 b
    std::cout << a << '\n';     // 20

    std::cout << (&r == &a) << '\n';   // 1：&r 就是 &a
    std::cout << sizeof(r) << '\n';    // 4：是被引用类型的大小，不是指针大小
}
```

### 4.4 需要说清的边界

- **C++ 标准并没有规定引用"不占存储"。** 编译器可以（而且常常真的）用地址或指针来实现引用。当引用**作为类成员、需要跨函数保存、或被取地址传递**时，通常确实会占用存储。
- 严格的说法是：**引用具有"别名语义"，语言不提供访问"引用自身地址"的手段**；实现层面可以有存储，只是你观察不到。
- 所以更准确的表述是：**引用是已有对象的别名，不产生新的对象；对引用做的一切操作都作用在它所绑定的那个对象上。**

### 4.5 引用 vs 指针

| 对比 | 引用 | 指针 |
| --- | --- | --- |
| 是否必须初始化 | 必须 | 不必须 |
| 能否为空 | 不能（没有空引用） | 可以 `nullptr` |
| 能否改绑 / 改指向 | 不能 | 可以 |
| 是否有自己的地址 | 语言层面没有；`&r` 是被引用对象的地址 | 有；`&p` 是指针变量自己的地址 |
| `sizeof` 结果 | 被引用类型的大小 | 指针的大小（64 位下 8 字节） |
| 能否做算术运算 | 不能 | 可以 |
| 常见用途 | 函数参数 / 返回值，避免拷贝又能修改实参 | 需要"可空""可改指向"的动态结构 |

### 4.6 常量引用

- `const int& cr = 42;` 是合法的：**常量引用可以绑定临时量**，并延长它的生存期。
- 所以函数传参常用 `const std::string&`：既避免拷贝，又保证不修改实参。
- 一句话：**引用是别名不是独立对象，`&r` 拿到的是被引用对象的地址；说它"没有自己的地址"在语言语义上是对的，但不要说成"一定不占内存"。**

## 5. 内联函数用 inline 声明"不能使用循环"——这个说法不成立

### 5.1 结论

**这个说法是错的。** C++ 标准从来没有规定 `inline` 函数不能包含循环，也没有规定不能有 `switch`、递归或任何其它控制流。

### 5.2 `inline` 的真实含义

| 作用 | 说明 |
| --- | --- |
| **解决 ODR 问题**（主要作用） | 允许同一个函数定义出现在**多个编译单元**（典型场景是写在头文件里）而不违反"单一定义规则"，链接器会把它合并成一份 |
| **优化建议**（次要作用） | 建议编译器把函数体直接**展开到调用处**，省掉函数调用开销。它**只是建议**，编译器可以完全忽略 |

### 5.3 "不能有循环"这个说法是怎么来的

- 来自 **C++98 时代的教材**：当时一些编译器只肯对"简单函数"做内联，一遇到循环、`switch`、递归就放弃展开，于是被写成了"内联函数不能有循环"。
- 那是**当时编译器的实现限制**，不是语言规则。
- **现代编译器**（GCC / Clang / MSVC）只要判断"内联划算"就会展开，函数里有循环**完全不构成障碍**；反过来，即使函数体里什么复杂结构都没有，编译器也可能因为别的原因拒绝内联。

### 5.4 真正影响"是否被内联"的因素

| 情况 | 影响 |
| --- | --- |
| 函数体很大 | 通常不展开（代码膨胀不划算） |
| 含循环 / 递归 | **只是降低可能性**，不是禁止 |
| 通过函数指针调用 | 编译期无法确定目标，通常不展开 |
| 虚函数经基类指针调用 | 通常不展开（目标能在编译期静态确定时才可以） |
| 函数被取地址 | 必须有实体存在，通常不展开 |
| 打开优化（`-O2` / `/O2`） | 显著提高展开概率 |
| Debug 模式 | 往往不展开，方便下断点调试 |

### 5.5 合法且常见的写法

```cpp
#include <vector>

inline int sum(const std::vector<int>& v) {   // 含循环，完全合法
    int s = 0;
    for (int x : v) s += x;
    return s;
}
```

### 5.6 几点补充

- **类内定义的成员函数默认就是 `inline`**（隐式内联），写在类体里的函数不需要再加 `inline`。
- `inline` 与宏的区别：宏是**文本替换**，没有类型检查、没有作用域；`inline` 函数有完整的类型检查和作用域，是更安全的替代方案。
- C++17 起 `inline` 还可以修饰**变量**（用于在头文件中定义全局变量）。
- 想确认"到底有没有真的内联"，要看汇编或编译器报告（GCC 的 `-Winline`、MSVC 的 `/Ob`），不能只看源码里写没写 `inline`。
- 一句话：**`inline` 的含义是"允许在头文件里重复定义 + 建议展开"，不是"限制函数体的复杂度"；含循环的内联函数既合法又常见。**

## 6. 五个说法的结论汇总

| # | 说法 | 结论 | 一句话 |
| --- | --- | --- | --- |
| 1 | 流输入、输出 | ✅ | `<<` / `>>` 是插入与提取，返回流引用所以能链式书写 |
| 2 | 格式控制 | ✅ | 用 `<iomanip>` 的操纵符；`setw` 只影响下一次，其它是粘性的 |
| 3 | 字符数据可以与整型数据运算 | ✅ | `char` 本质是整型，运算时提升为 `int`，`'5' - '0' = 5` |
| 4 | 引用不是变量，自身没有地址 | ⚠️ 基本正确 | 语言层拿不到引用自身的地址，`&r` 就是被引用对象的地址；但标准不保证"不占存储" |
| 5 | `inline` 函数不能使用循环 | ❌ 错误 | 标准从未禁止，是否展开由编译器决定 |
